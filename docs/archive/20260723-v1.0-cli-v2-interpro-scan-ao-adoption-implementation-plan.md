# Biofetch CLI v2, InterProScan, and AO Adoption Implementation Plan

Version: v1.0
Date: 2026-07-23
Status: archived; completed by the 2026-07-24 closeout

## Goal

Deliver one coherent next version of `biofetch` that:

- replaces the current implementation-shaped CLI options with a GNU-style,
  Cobra-native public CLI;
- adds versioned, resumable, integrity-checked InterProScan distribution
  downloads under `biofetch interpro scan`;
- completes the repository-owned Agent Orchestrator (AO) adoption contract and
  proves the external review-continuation loop; and
- keeps the existing raw-resource and `manifest.lock` ownership boundary
  intact.

The CLI migration is intentionally breaking. The approved migration does not
retain aliases for old commands or options.

## Settled Decisions

### CLI

1. Use lowercase kebab-case for long options.
2. Use an operand for an unambiguous required primary input.
3. Use `-o` / `--output` for generated or downloaded output.
4. Keep internal Go configuration names independent from public flag spelling.
5. Keep `fetch` and `lock`; rename `sync` to `restore`.
6. Keep domain terms such as `go`, `kb`, `uniref`, `brite`, and `gmt`.
7. Rename implementation-shaped command tokens:
   - `omnipath enz_sub` to `omnipath enzyme-substrate`;
   - `uniprot idmapping` to `uniprot id-mapping`.
8. Do not mechanically rename asset selector values. Preserve values that are
   upstream identifiers, manifest identities, filenames, or established
   repository terminology.
9. Remove the implicit `@file` value syntax. Use explicit optional list-file
   flags where large selections are material.
10. Add root `--version` and Cobra shell completion commands.
11. Do not retain deprecated aliases. Tests must show that removed spellings
    are rejected.

### InterProScan

1. Add `scan` as a sibling of `interpro mapping`.
2. Require a fixed InterProScan version for the first release; do not implement
   `current` or latest-release discovery.
3. Accept versions shaped like `5.77-108.0` and reject unsafe or ambiguous
   tokens before network or filesystem writes.
4. Require `--allow-large-downloads` for fetch.
5. Preserve both the distribution archive and its upstream `.md5` file under
   `raw/`.
6. Verify the upstream MD5 before the archive's `.part` file is atomically
   renamed.
7. Continue recording repository-standard SHA256, bytes, and final URL in
   `manifest.lock`; MD5 is an additional upstream publication check, not a
   replacement for SHA256.
8. Do not extract or install InterProScan. Those are downstream deployment
   responsibilities.

### AO

1. Add only the smallest repository-owned AO increment to root `AGENTS.md`.
2. Keep host service configuration, proxy behavior, pinned AO patches, and
   diagnostic timeout changes in the accepted calibration AO runbook and
   initializer, not in this repository.
3. Treat the repository as `runtime-ready` until a real Automatic Codex Review
   finding returns to the original worker and that worker pushes a verified
   correction.
4. Keep auto-merge disabled and leave merge and risk decisions to the user.
5. Use an isolated worktree fallback if AO is unavailable.

## Target CLI Contract

### Fetch

```bash
biofetch interpro scan fetch \
  --output /database/bioinfo/resources/interpro \
  --version 5.77-108.0 \
  --allow-large-downloads \
  --on-existing skip \
  --max-attempts 5 \
  --retry-wait 3s \
  --workers 1 \
  --log-dir /tmp/biofetch-logs
```

Fetch retains an option for output because the primary input is the implicit
upstream database asset.

### Lock

```bash
biofetch interpro scan lock \
  /database/bioinfo/resources/interpro/scan/5.77-108.0 \
  --workers 4
```

The snapshot directory is the required primary input and is therefore an
operand.

### Restore

```bash
biofetch interpro scan restore \
  /database/bioinfo/resources/interpro/scan/5.77-108.0 \
  --on-existing skip \
  --max-attempts 5 \
  --retry-wait 3s
```

Restore reads identity and source URLs from the snapshot's `manifest.lock`.
It does not require a separate output root or version option.

### Aggregate Manifest

```bash
biofetch manifest build \
  /database/bioinfo/resources \
  --output /database/bioinfo/meta \
  --formats toml,json
```

The resource root is the required primary input. The generated manifest
directory remains an output option.

## Implementation Design

### Shared CLI Boundary

Converge all public option binding through `internal/shared/cliopt` where the
semantics are genuinely shared:

- output;
- snapshot operand validation;
- lock workers;
- duration-based retry and request interval;
- existing-file policy;
- dry-run, progress, logging, and TLS policy.

Do not force database-specific selectors or source-resolution policy into the
shared package. Keep each command's main path locally readable.

Root command construction must expose build version information and generated
Cobra completion commands without adding a second CLI framework.

### Restore Boundary

Refactor current `sync` entrypoints to accept one exact snapshot directory.
Derive the database asset, version token, and source records from the snapshot
and its `manifest.lock`. Preserve current SHA256-based reuse and restoration
behavior.

Do not keep parallel `sync` and `restore` paths. The migration lands as one
public interface replacement.

### Download Verification Hook

Extend `staticasset.Asset` with a non-serialized, domain-supplied downloaded
file verifier. Invoke it on the completed `.part` file before final rename and
before a file record is written. A verifier failure must:

- leave no final archive;
- leave no manifest record claiming the archive is valid;
- return an error that names the asset and failed verification; and
- retain or remove the `.part` file according to one documented retry policy.

The hook owns lifecycle timing only. InterPro-specific MD5 parsing and
calculation remain in `internal/interpro`.

### InterProScan Fetch Sequence

1. Validate output, fixed version, retry policy, duration values, and the
   explicit large-download opt-in before network or filesystem writes.
2. Build the fixed release directory and filenames from the validated version.
3. Fetch the small `.md5` asset through `staticasset.Fetch`, producing a valid
   partial manifest if the archive has not yet completed.
4. Parse exactly one MD5 and filename pair and require the expected archive
   filename.
5. Run `staticasset.Fetch` with both assets. Reuse the already locked `.md5`
   file and attach the expected MD5 verifier to the archive asset.
6. Resume or download the archive, validate its `.part` bytes, rename it, then
   compute and record SHA256 through the existing staticasset path.
7. Write the complete deterministic manifest.

This two-stage use of `staticasset.Fetch` avoids a second downloader and makes
interruption after the checksum download recoverable.

### InterProScan Lock and Restore

- `lock SNAPSHOT` derives and validates the fixed version from the snapshot
  directory.
- When both official files are present, lock verifies the MD5 relationship
  before publishing a new manifest.
- `restore SNAPSHOT` trusts the manifest's SHA256 records for recovery and does
  not depend on mutable latest-release metadata.
- Neither command extracts the archive.

## Delivery Slices

Complete the external AO doctor prerequisite below before Slice 1. Then execute
each repository slice through its owning AO worker; if AO is unavailable, use
the documented isolated-worktree fallback and report that bounded fallback.

### Slice 1: Repository-Owned AO Intake

Files:

- `AGENTS.md`
- `docs/README.md` only if navigation needs adjustment

Work:

- start a task-specific AO worker before creating the implementation branch or
  PR;
- add the repository map, validation entrypoints, permission boundaries, and AO
  delivery section;
- verify every referenced path and command from a clean checkout;
- start the next implementation task through AO after this repository contract
  is merged.

Acceptance:

- a new agent can find current docs and validation without conversation state;
- AO project readback still matches the accepted `biofetch` configuration;
- fallback and human-authority boundaries are explicit.

### External Control-Plane Prerequisite: AO Doctor

Owner: the accepted calibration AO runbook and installer, not this repository.

Work:

- classify the GitHub probe timeout against the measured proxied `gh api`
  latency;
- prefer a bounded diagnostic timeout increase or network correction over
  weakening token validation;
- if the pinned AO source is patched, rebuild from the pinned source and patch
  set, rerun targeted AO tests, install, restart, and verify binary hashes;
- rerun `ao doctor --json` until it has zero failures;
- read back service and `biofetch` project state after restart.

This step must not be represented as a biofetch code change.

### Slice 2: Atomic CLI v2 Migration

Files:

- `internal/shared/cliopt`
- every database CLI package
- `internal/biofetch`
- CLI contract tests
- root README, architecture contract, and test contract
- repository scripts and CI references, if affected

Work:

- introduce snapshot and resource-root operands;
- use native duration values;

- removed spellings fail as unknown commands or flags;
- every new help path is reachable;

- the current snapshot layout and manifest schema remain compatible.

### Slice 3: InterProScan Distribution

Files:

- `internal/interpro/cli.go`
- a focused InterProScan implementation file and tests
- `internal/shared/staticasset` verifier hook and tests
- root CLI contract tests
- README and resource/test contracts

Work:

- add `interpro scan fetch|lock|restore`;
- implement fixed version and URL resolution;
- download and preserve `.md5` plus archive;
- validate MD5 before rename and retain SHA256 manifest recording;
- add large-download safety and focused failure behavior.

Acceptance:

- the reference version produces the declared snapshot identity and paths;
- checksum mismatch cannot produce a valid final archive or manifest record;
- interrupted archive downloads resume through the existing `.part` path;
- second fetch reuses verified files;
- lock and restore operate on the snapshot operand;
- no extraction or installation behavior is introduced.

### Slice 4: AO Review-Continuation Canary

Owner: AO plus GitHub Automatic Codex Review.

Work:

- use an AO-owned worker and isolated workspace;
- open a bounded disposable PR with auto-merge disabled;
- request Automatic Codex Review;
- require a real anchored, actionable review finding;
- confirm AO delivers it to the original worker;
- have that worker make, validate, and push the correction;
- read back the corrected commit, CI, review-thread state, and AO session;
- close or merge the canary only under explicit user authority.

If Automatic Review produces no actionable finding, the canary is
inconclusive, not passed. Do not seed a defect into a production change that
could be merged accidentally.

Acceptance:

- the original worker receives and repairs a real review finding;
- repository validation passes on the correction;
- the correction is visible on the remote PR;
- auto-merge remains off;
- only then may biofetch be labeled `continuation-proven`.

## Test Plan

### CLI Contract

Add table-driven root tests covering:

- every database, asset, and action help path;
- root `--version` and completion commands;
- fetch `--output`;
- lock and restore snapshot operands;
- manifest build resource-root operand and `--output`;
- duration parsing;
- new boolean and policy spellings;
- rejection of every removed command and flag;
- preservation of reviewed asset selector values.

Use help and parse tests to enforce the public surface, not implementation
field names.

### Static Asset Verification

Use `httptest` and temporary directories to cover:

- verifier called before final rename;
- success writes the final file and manifest record;
- mismatch leaves no final file or valid record;
- retry behavior after verification failure;
- resumed `.part` verification;
- verifier exclusion from TOML serialization;
- unchanged behavior for assets without a verifier.

Run the race detector because the hook is exercised in the bounded parallel
download path.

### InterProScan

Cover:

- accepted and rejected version tokens;
- exact archive and `.md5` URLs;
- MD5 file parsing, filename binding, malformed content, and mismatch;
- large-download opt-in before side effects;
- first fetch, interrupted fetch, reuse, lock, and restore;
- manifest identity, paths, bytes, URL, and SHA256;
- dry-run behavior without network or filesystem writes.

### Real Artifact Acceptance

Before claiming InterProScan completion:

1. Verify the local reference artifact's size, MD5, and SHA256 against the
   values recorded in this plan.
2. Exercise `interpro scan lock` on a temporary snapshot containing the
   official archive and `.md5` without copying or modifying the source
   artifact unnecessarily; prefer a safe hard link only when the filesystem
   supports it.
3. Inspect the resulting `manifest.lock` and aggregate manifest.
4. Perform one full upstream fetch into an explicitly approved temporary
   location to validate real HTTP resume, upstream MD5, final SHA256, and
   second-run reuse.
5. Remove only the explicitly created temporary acceptance snapshot after
   recording the required hashes and manifest evidence.

The full upstream fetch is approximately 7 GB. If it is not run, report the
exact skipped command and retain the residual live-download risk; unit tests
and an existing manually downloaded artifact do not fully prove the production
HTTP path.

## Risks and Controls

| Risk | Control |
| --- | --- |
| mixed old and new CLI on `main` | migrate every command family atomically in Slice 2 |
| scripts silently use removed options | repository-wide search plus negative CLI tests |
| `restore` changes behavior while being renamed | preserve SHA256 recovery semantics and add behavior tests before deleting `sync` |
| 7 GB download is interrupted | reuse existing resumable `.part` path |
| corrupt archive is renamed | verify upstream MD5 before atomic rename |
| upstream MD5 is mistaken for repository integrity | continue recording SHA256 in `manifest.lock` |
| InterPro mapping and scan versions are conflated | separate `mapping` and `scan` assets and validators |
| AO is called complete from static status | require the real review-continuation canary |
| AO host changes leak into repository | keep service patches and proxy policy in calibration |
| destructive cleanup removes user data | use explicit temporary acceptance roots and exact-target cleanup only |

## Completion Criteria

This plan is complete only when:

- the repository exposes one documented CLI v2 with no compatibility aliases;
- old public spellings are mechanically rejected;
- InterProScan fetch, lock, and restore pass local and approved real-artifact
  acceptance;
- final archives are upstream-MD5-verified and manifest-SHA256-recorded;
- current architecture and test contracts describe the delivered behavior;
- `AGENTS.md` provides the repository-owned AO and fallback entrypoint;
- AO doctor has zero failures under the accepted host profile;
- a real Automatic Codex Review finding has completed the original-worker
  repair loop;
- remote PR and CI state have been read back; and
- auto-merge and merge authority remain with the user.
