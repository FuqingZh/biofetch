# Biofetch test contract

Version: v1.2
Date: 2026-07-31
Status: current

## Purpose

The test suite protects downloader ownership, snapshot reproducibility, CLI
compatibility, and deterministic aggregate manifests. Tests are organized by
the Go package that owns the behavior; the repository does not use artificial
`unit/` and `integration/` directory layers.

## Test layers

### Local package tests

The default suite is offline-safe. Tests use `t.TempDir`, in-memory readers,
and `httptest` servers rather than live upstream services or CephFS writes.
Package tests cover URL and path resolution, input validation, retry and resume
behavior, manifest encoding, deterministic ordering, and error recovery.

Shared helpers have direct tests when they own durable behavior:

- `cliopt`: CLI token expansion and validation;
- `confirm`: destructive-operation confirmation prompts;
- `filehash` and `parallel`: hashing and ordered concurrency;
- `httpx`: resumable downloads and HTTP behavior;
- `logx`: run-log lifecycle;
- `sets`: deterministic set ordering;
- `staticasset`: raw-only acquisition and lock behavior;
- `tomlx`: optional reads and atomic TOML replacement.

### Public CLI contract tests

`internal/biofetch/cli_test.go` is the root command contract. It verifies:

- removed derived routes remain unavailable;
- STRING exposes `network` and `catalog` assets;
- every snapshot `lock` and `restore` uses one exact snapshot operand, with
  nested-path coverage, and neither accepts `--output` nor `--version`;
- all maintained fetch flags use kebab-case, durations use Cobra-native
  duration parsing, and material list inputs expose explicit `*-file` options;
- removed `sync`, `enz_sub`, `idmapping`, underscore flags, and implicit
  `@file` syntax are rejected;
- root version and generated shell completion commands are reachable;
- aggregate manifest output uses `--output`, fixed filenames, and rejects the
  removed underscore-style options.

The maintained action matrix includes `interpro scan fetch|lock|restore`.
Contract tests require its fixed `--version`, `--allow-large-downloads`, exact
snapshot operands, and rejection of `sync` and underscore-style safety flags.

### InterProScan integrity checks

InterProScan tests use local `httptest` fixtures rather than the approximately
7 GB production artifact. They cover unsafe version rejection before network
or filesystem writes, the large-download gate, exact HTTPS path construction,
strict MD5 parsing and filename binding, mismatch behavior, removed `.part`
policy with clean subsequent redownload, corrected-checksum recovery,
overwrite-safe checksum reuse, interrupted download resume, reuse, complete
manifest identity, partial-manifest restore rejection, lock-time MD5
verification, fresh-lock fixed URL publication without network access,
undeclared scratch-file exclusion, and exact-manifest SHA256 restore.
Successful chunked downloads remove their temporary `.part.parts` workspace
after merging.

The shared `staticasset` tests prove that a downloaded-file verifier runs on a
completed `.part` before rename and manifest recording. On verifier failure,
the `.part` is removed and the call returns immediately without consuming
additional retry attempts; a later invocation therefore downloads from zero.

### Manifest contract tests

`internal/manifest` tests must cover all supported formats from one model,
fixed output names, physical path resolution, child-lock validation, duplicate
snapshot identity rejection, unsafe file paths, failure cleanup, and
byte-identical repeated builds.

### OmniPath full-evidence and Reactome release checks

OmniPath live-interaction tests use injected HTTP transports and temporary
directories. They cover academic/commercial query identity, default academic
behavior, fixed evidence fields, DoRothEA A-D defaults, capability validation,
bounded leaf planning, 429 waits, 502/503 bisection, singleton failure, table
and JSON validation, exact inventory edge sets, start/end drift, deterministic
canonical sidecar-based lock rebuild, strict legacy capability metadata,
stale-staging rejection, restore path confinement, and restore drift without
published-file or manifest mutation. Full-evidence tests also require default
lock/restore logs to remain outside the snapshot.

Reactome tests simulate the current-version endpoint. They cover 429 and all
5xx statuses including 521, per-attempt `Retry-After`, exhaustion identity,
final transport status, immutable release URLs, and full fetch orchestration
that bypasses discovery for an explicit version.

### Concurrency checks

Run the race detector for shared hashing and the custom STRING scanner when
their concurrency changes:

```bash
GOCACHE=/tmp/biofetch-race go test -race \
  ./internal/shared/staticasset \
  ./internal/shared/filehash \
  ./internal/shared/parallel \
  ./internal/stringdb
```

When the downloaded-file verifier or InterProScan download path changes, also
run:

```bash
GOCACHE=/tmp/biofetch-race go test -race \
  ./internal/shared/staticasset \
  ./internal/interpro
```

## Required local gate

```bash
GOCACHE=/tmp/biofetch-test go test ./...
GOCACHE=/tmp/biofetch-test go vet ./...
GOCACHE=/tmp/biofetch-test go build -o /tmp/biofetch ./cmd/biofetch
```

Also inspect root help, `--version`, shell completion, every action help path,
and `manifest build --help` from the built binary when a public CLI changes.
Statement coverage is diagnostic evidence, not a numeric
merge gate; prioritize contract branches and failure modes over percentage
inflation.

## Real-resource acceptance

CephFS acceptance is read-only with respect to the resource tree. Write
aggregate outputs and logs under `/tmp`, then verify:

- all incompatible locks are reported together and no formal output remains;
- a successful build reports snapshot/file/byte totals;
- repeated builds at the same output location are byte-identical;
- aggregate building hashes child `manifest.lock` files only;
- snapshot locking performs full file hashing and never substitutes size or
  mtime for content integrity.

Real-resource acceptance is required before publishing manifest-contract or
lock-performance changes, but it is not part of the default offline suite.
OmniPath live smoke tests, when needed, must use a disposable `/tmp` resource
root and must not write CephFS.
