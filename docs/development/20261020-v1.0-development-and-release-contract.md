# Development and release contract

Version: v1.0
Date: 2026-10-20
Status: current

## Authority and ownership

Direct Codex development supersedes the historical AO adoption requirement.
Do not start AO, restore retired workers, or claim PRs merely to implement,
test or release. Preserve unrelated changes and other owners' workspaces.
Use a task branch; isolate it when the maintained checkout is dirty.

The coordinator owns implementation, review, validation and delivery until the
authorized outcome is verified. Existing user authorization for merge,
publication or resource acquisition persists; ordinary implementation does not
grant those external actions. No background follow-up is promised without a
verified wakeup mechanism.

## Proportional local verification

State the completion claim and affected seam before choosing checks:

| Change | Initial local verification |
| --- | --- |
| Documentation only | Check current authority, links and executable examples |
| One source adapter | `go test` and `go vet` for its package and `internal/biofetch` |
| Shared download, manifest or hashing behavior | Changed helper plus all direct consumers; scoped `go test -race` |
| Public CLI | Root/version/completion and all maintained action help contract tests |
| Dependencies or packaging | Module consistency, notices, build and distribution checks |
| Release candidate | Complete gate below once on the final source |

Use the `toolchain` from `go.mod`, for example
`GOTOOLCHAIN=go1.26.9 go test ./internal/complexportal ./internal/biofetch`.
Tests use disposable directories and deterministic local HTTP fixtures.
No default test contacts live providers or writes shared resource trees.
New checks include a counterexample they must reject.

The release candidate gate is:

```bash
go test ./...
go vet ./...
go test -race ./...
go build -trimpath -o /tmp/biofetch ./cmd/biofetch
go mod tidy -diff
go mod verify
python3 scripts/generate_third_party_notices.py --check
go run honnef.co/go/tools/cmd/staticcheck@2025.1.1 ./...
go run golang.org/x/vuln/cmd/govulncheck@v1.4.0 ./...
```

Run these using the declared toolchain, stopping on the first failure.
Passing evidence remains valid for unchanged source. Repeat affected checks
after fixes; broaden only for uncovered consumers or an explicit gate.
Do not rerun full local regression for review polling, prose-only changes,
tag creation or release readback.

## Integration and publication

The GitHub workflows and active repository ruleset define remote gates;
this document does not waive them. The required PR status is
`validate-biofetch`; inspect exact-head checks and unresolved review threads
before an authorized merge. Review new feedback and preserve evidence on
failure. Do not bypass a failing required check.

For an authorized release:

1. Merge the reviewed change after exact-head CI passes.
2. Verify the merged source and required main checks.
3. Create a new immutable semantic-version tag on that source.
4. Let `.github/workflows/release.yml` validate, build both architectures,
   smoke-test native binaries, generate checksums/SBOM, attest and publish.
5. Read back the release and assets; verify downloaded archive checksums,
   provenance, embedded source revision and CLI behavior.
6. Use the published binary for separately authorized real-data acceptance.

`v0.1.0` was published on 2026-08-14. Earlier readiness documents saying the
first release remains pending describe their historical state; current release
state comes from GitHub Releases and tag/workflow evidence.

## Resource acquisition

Software publication does not itself publish upstream database content.
Acquire only the requested source and version into its own resource namespace,
using fixed upstream URLs and per-snapshot locks. Verify file counts, byte
counts, hashes and declared inventory. Preserve incomplete acquisitions as
retryable state without claiming acceptance.

Adding raw snapshots does not normalize them, admit them to a downstream
catalog, or republish an existing global resource release. Those boundaries
remain with their owning contracts.
