# Diamond UniProt Annotation Resources PR Roadmap

Version: v1.0
Date: 2026-05-31
Status: current

## Goal

Add official or quasi-official raw resource downloads needed for the
`diamond-uniprot` annotation route after a query protein has been assigned a
UniProt accession.

Already covered resources are out of scope here:

- UniProt ID mapping
- GO ontology
- Reactome UniProt2Reactome
- WikiPathways GMT
- UniProt subcellular location
- KEGG pathway, BRITE, and pathway class downloads

This roadmap covers the remaining gaps:

- UniProtKB FASTA for building or auditing `uniprot.dmnd`
- KEGG organism and gene mapping resources
- eggNOG mapper resources for OG and COG annotation
- InterPro/Pfam protein-domain mapping resources

## Source Contracts

### UniProtKB FASTA

Purpose:

- provide the official sequence source for building or validating
  `uniprot.dmnd`
- record provenance for an existing local `uniprot.dmnd` without pretending
  the `.dmnd` itself is an official UniProt asset

Official sources:

- `current_release/relnotes.txt`
- `current_release/knowledgebase/complete/uniprot_sprot.fasta.gz`
- `current_release/knowledgebase/complete/uniprot_trembl.fasta.gz`
- optional: `current_release/knowledgebase/complete/uniprot_sprot_varsplic.fasta.gz`

Command shape:

```bash
biofetch uniprot kb fetch \
  --dir_out /data/uniprot \
  --assets sprot,trembl \
  --should_allow_large_download
```

Directory:

```text
<dir_out>/kb/<version_token>/
  raw/
    knowledgebase/complete/uniprot_sprot.fasta.gz
    knowledgebase/complete/uniprot_trembl.fasta.gz
  manifest.lock
```

Rules:

- omitted `--version` and `--version current` must resolve a real UniProt
  release token from `relnotes.txt`, such as `2026_01`
- `raw/` preserves official relative layout
- `--base_url_current_release` should be shared with UniProt idmapping mirror
  support
- direct download of third-party `uniprot.dmnd` is not a first-class fetch
  path; if an existing `.dmnd` is already present, add a lock/registration
  command that records FASTA provenance, DIAMOND version, build command, bytes,
  and SHA256

### KEGG Mapping Core

Purpose:

- build `UniProt/GeneId -> KEGG gene -> KO/pathway` mappings
- support species-aware KEGG annotation derived from UniProt hits

Official KEGG REST sources:

- `list/organism`
- `conv/<org>/uniprot`
- `conv/<org>/ncbi-geneid`
- `list/<org>`
- `link/ko/<org>`
- `link/pathway/<org>`
- `link/pathway/ko`

Command shape:

```bash
biofetch kegg mapping fetch \
  --dir_out /data/kegg \
  --organisms hsa,mmu \
  --assets organism,conv_uniprot,conv_ncbi_geneid,gene_list,gene_ko,gene_pathway,ko_pathway
```

Directory:

```text
<dir_out>/mapping/<snapshot_token>/
  raw/
    organism/list_organism.tsv
    hsa/conv_uniprot.tsv
    hsa/conv_ncbi_geneid.tsv
    hsa/gene_list.tsv
    hsa/gene_ko.tsv
    hsa/gene_pathway.tsv
    ko/ko_pathway.tsv
  manifest.lock
```

Rules:

- KEGG mapping is snapshot-based because KEGG REST does not expose a stable
  release token for these calls
- `--should_download_all` means all KEGG organisms from `list/organism`, and
  should require explicit confirmation
- `ko_pathway` is global and should be downloaded once per snapshot, not once
  per organism
- respect existing KEGG request interval and retry policy

### eggNOG / COG

Purpose:

- provide `protein/member -> OG` and `OG -> description / taxonomic level /
  COG_categories`
- resource COG category definitions instead of hardcoding category code names

Quasi-official sources:

- eggNOG-mapper database downloads, including mapper annotation databases and
  DIAMOND search database when available
- NCBI COG category definitions only when eggNOG does not ship a suitable
  category table for the selected version

Command shape:

```bash
biofetch eggnog mapper fetch \
  --dir_out /data/eggnog \
  --version 7 \
  --assets db,taxa,diamond \
  --should_allow_large_download

biofetch eggnog cog fetch \
  --dir_out /data/eggnog \
  --assets category_definition
```

Directory:

```text
<dir_out>/mapper/<version_token>/
  raw/
    eggnog.db.gz
    eggnog.taxa.db.gz
    eggnog_proteins.dmnd.gz
  manifest.lock

<dir_out>/cog/<version_token>/
  raw/
    cog_categories.tsv
  manifest.lock
```

Rules:

- confirm actual eggNOG v7 file names and index layout before implementation
- unlike UniProt `.dmnd`, `eggnog_proteins.dmnd` is part of the eggNOG-mapper
  data distribution and can be treated as a raw upstream asset
- COG category definitions should be versioned and manifest-locked
- if the eggNOG data source only provides uncompressed SQLite or `.dmnd` files,
  keep the upstream file names and do not invent compressed names

### InterPro / Pfam

Purpose:

- build `UniProt -> InterPro/Pfam` mappings
- provide entry metadata for InterPro and Pfam IDs

Official EBI sources:

- `https://ftp.ebi.ac.uk/pub/databases/interpro/current_release/protein2ipr.dat.gz`
- `https://ftp.ebi.ac.uk/pub/databases/interpro/current_release/interpro.xml.gz`
- optional future source: `match_complete.dat.gz` when domain coordinates are
  required

Command shape:

```bash
biofetch interpro mapping fetch \
  --dir_out /data/interpro \
  --assets protein2ipr,entries \
  --should_allow_large_download
```

Directory:

```text
<dir_out>/mapping/<version_token>/
  raw/
    protein2ipr.dat.gz
    interpro.xml.gz
  manifest.lock
```

Rules:

- prefer an `interpro` root command over a separate `pfam` root because Pfam
  is distributed and documented through InterPro for these mapping needs
- first implementation only downloads raw assets; parsing XML into compact
  entry tables belongs in a later tidy/build step
- `protein2ipr.dat.gz` is a large file and requires
  `--should_allow_large_download`

## PR Roadmap

### PR 1: UniProtKB FASTA Downloads

- Add `biofetch uniprot kb fetch|lock|sync`.
- Reuse UniProt current release parsing and mirror base support.
- Support `--assets sprot,trembl,varsplic`.
- Add large-download guard for `trembl`.
- Tests: source URL construction, release parsing, mirror base, large-download
  guard, manifest identity.

### PR 2: KEGG Mapping Core

- Add `biofetch kegg mapping fetch|lock|sync`.
- Implement organism-scoped REST asset resolution and one global
  `ko_pathway` asset.
- Support `--organisms`, `@file`, and `--should_download_all`.
- Tests: organism list parsing, URL construction, all-organism confirmation,
  deterministic raw paths, manifest reuse.

### PR 3: InterPro Mapping Downloads

- Add `biofetch interpro mapping fetch|lock|sync`.
- Support `--assets protein2ipr,entries`.
- Resolve current InterPro version from an authoritative release marker when
  available; otherwise use a clearly named snapshot token with locked URLs and
  hashes.
- Tests: asset selection, large-download guard, manifest identity, sync.

### PR 4: eggNOG Mapper and COG Resources

- Add `biofetch eggnog mapper fetch|lock|sync` after confirming current v7
  file names.
- Add `biofetch eggnog cog fetch|lock|sync` for category definitions.
- Tests: index parsing, version selection, asset selection, large-download
  guard, manifest identity.

### PR 5: Existing `uniprot.dmnd` Registration

- Add a registration or lock command for existing local `uniprot.dmnd`.
- Record source FASTA version, reviewed/reference/full policy, header format,
  DIAMOND version, command line, file bytes, and SHA256.
- Do not download third-party `uniprot.dmnd` as an official asset.

## Acceptance Criteria

- Every new resource writes `manifest.lock` with final URL, bytes, and SHA256.
- All `current` pointers either resolve to a real release token or fail before
  writing output.
- Large files require `--should_allow_large_download`.
- `raw/` preserves upstream layout where the upstream layout is meaningful.
- Derived files such as `.dmnd` have explicit build or registration metadata
  and are not labeled as official downloads unless upstream actually ships
  them.
