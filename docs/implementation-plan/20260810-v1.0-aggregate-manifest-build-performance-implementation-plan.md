# Aggregate manifest v2 and build performance implementation plan

Version: v1.0
Date: 2026-08-10
Status: implemented; v2 candidate verified; consumer/publication gate pending
Estimate: 3-4 engineer-days

## Goal

Publish one decision-complete aggregate manifest v2 implementation that both
models dataset-qualified snapshots correctly and reduces
`biofetch manifest build RESOURCE-ROOT` wall-clock time on the production
CephFS resource tree. The implementation must not weaken snapshot integrity or
read the large raw files referenced by child locks.

The first implementation slice must:

1. add optional aggregate snapshot field `dataset` and change aggregate
   identity to `(database, asset, dataset, version)`;
2. emit only `biofetch-manifest-v2`, with one documented TOML/JSON model and a
   matching TSV `Dataset` column;
3. stop recursively enumerating payload, derived, log, and incomplete staging
   trees that cannot contain authoritative snapshot locks;
4. retain arbitrary-depth resource namespaces such as
   `omnipath/interactions/<dataset>/<version>`;
5. read, parse, hash, and validate discovered `manifest.lock` files with
   deterministic bounded concurrency;
6. preserve ordered validation errors, qualified duplicate detection, atomic
   output, and
   byte-identical repeated builds for a fixed valid input tree; and
7. establish reproducible schema, compatibility, offline, and read-only CephFS
   acceptance gates.

This plan is implementation authority for aggregate v2 and aggregate-build
performance as one coordinated delivery. Dataset identity is included because
the current full resource tree cannot produce a valid aggregate without it.
The maintained
[resource and manifest contract](../architecture/resource-manifest-contract.md),
[test contract](../testing/20260717-v1.0-test-contract.md), and
[CephFS benchmark](../benchmarks/20260717-v1.0-cephfs-lock-and-manifest-benchmark.md)
remain authority for snapshot ownership, integrity, publication, and test
boundaries.

## Non-goals

- Do not stat, open, or rehash raw files referenced by child `[[files]]`
  records. Aggregate build continues to hash only each `manifest.lock`.
- Do not replace child lock SHA256 with size, mtime, inode, Ceph metadata, or a
  cached trust decision.
- Do not add an incremental manifest cache or persistent resource index in the
  first slice. The measured 38.5 MB of child locks is not the primary
  bottleneck.
- Do not parallelize directory discovery in the first slice. Unbounded CephFS
  metadata concurrency can increase contention and make traversal less
  predictable.
- Do not hard-code a fixed snapshot depth. The current tree contains both
  three-component and four-component snapshot paths.
- Do not change child snapshot `database`, `asset`, `dataset`, `version`,
  `version_token`, query, or license fields. Aggregate v2 consumes the existing
  optional child `dataset`; it does not rewrite child locks.
- Do not add `license`, query fields, or a generic qualifier map to aggregate
  v2. Live OmniPath academic/commercial snapshots already have distinct
  `version_token` values because the canonical query fingerprint covers
  dataset and license. Historical archive acquisition is academic-only.
- Do not emit aggregate v1 and v2 in parallel or add a schema-selection flag.
  One maintained writer emits v2; the previously published v1 artifact remains
  readable as historical output until v2 publication passes its consumer gate.
- Do not update or publish the production
  `/database/bioinfo/meta/manifest.toml`. Real-resource acceptance writes only
  to a unique directory below `/tmp`; a CephFS publication remains a separate
  explicitly authorized operation.
- Do not add a public deep-audit command in this slice. If operators require an
  on-demand scan for locks illegally nested below an authoritative snapshot,
  specify `manifest verify` separately after the fast-path contract is proven.

## Aggregate v2 dataset identity contract

### Evidence and decision

The current production resource tree contains three historical OmniPath
snapshots with the same v1 identity fields:

```text
database = omnipath
asset = interactions
version_token = 2025-08-13
```

Their paths and source-defined `dataset` values differ:

```text
omnipath/interactions/collectri/2025-08-13   dataset = collectri
omnipath/interactions/dorothea/2025-08-13    dataset = dorothea
omnipath/interactions/kinaseextra/2025-08-13 dataset = kinaseextra
```

Aggregate v1 ignores `dataset` and defines uniqueness as
`(database, asset, version)`. A minimal `/tmp` build using these three current
locks was verified on 2026-08-10 to accept CollecTRI first and then report two
duplicate identities for DoRothEA and KinaseExtra.

Aggregate v2 resolves the modeling defect by preserving the upstream field as
an optional typed snapshot qualifier:

```text
(database, asset, dataset, version)
```

This is preferable to inventing different version values, deriving
`interactions/<dataset>` as a synthetic asset, or treating filesystem path as
an implicit identity field. `interactions` and `dataset` are distinct upstream
concepts and remain distinct in the aggregate model.

### Schema model

The aggregate schema token becomes:

```toml
schema_version = "biofetch-manifest-v2"
```

Each snapshot gains one optional field after `asset`:

```toml
[[snapshots]]
database = "omnipath"
asset = "interactions"
dataset = "collectri"
version = "2025-08-13"
```

Contract:

- `lockEnvelope` represents child `dataset` as optional so absence can be
  distinguished from an explicitly malformed empty value;
- `snapshot.dataset` is emitted only when non-empty in TOML and JSON;
- child locks without `dataset` remain valid and map to the empty dataset
  qualifier;
- a present value must be non-empty and already equal to its trimmed form; it
  is otherwise preserved verbatim rather than inferred or renamed;
- the aggregate identity key is the exact tuple
  `(database, asset, dataset, version_token)`, using empty dataset for ordinary
  assets;
- duplicate rejection applies within the complete four-part identity;
- snapshots sort by `database`, `asset`, `dataset`, `version`, then `path`;
- `version` in aggregate output continues to mean child `version_token`; and
- child `version` continues to populate `source_version` only when it differs
  from `version_token`.

Do not infer `dataset` from the snapshot path. A nested path without a typed
child `dataset` remains an empty-dataset snapshot, and a child `dataset` remains
authoritative regardless of directory depth. This keeps identity sourced from
the lock rather than from layout coincidence.

### TSV contract

TOML remains the canonical default and JSON mirrors the same model. The
flattened TSV adds PascalCase header `Dataset`, following the repository's
existing exported-header convention. It is inserted between `Asset` and
`Version`:

```text
SchemaVersion ResourceRoot Database Asset Dataset Version SourceVersion ...
```

Rows for snapshots without a dataset contain an empty `Dataset` field. Do not
append the column at the end: keeping identity fields together makes the public
record shape auditable.

### v1 compatibility and publication

Aggregate v2 is an intentional schema break:

- the schema token changes from `biofetch-manifest-v1` to
  `biofetch-manifest-v2`;
- TOML and JSON may contain `dataset`;
- the TSV header and every TSV row gain one column; and
- duplicate identity semantics add the dataset qualifier.

The builder emits only v2. Do not add `--schema-version`, dual-output files, or
a compatibility writer because parallel formats would create two authorities
and an unclear retirement path.

Before replacing a published v1 aggregate, identify every consumer of
`manifest.toml`, `manifest.json`, and `manifest.tsv` and prove one of:

1. it accepts schema v2, treats absent `dataset` as empty, and reads TSV by
   header name; or
2. it has been updated and validated against the v2 fixture.

The existing published v1 file remains the rollback authority until that gate
passes. Biofetch may merge and benchmark the v2 implementation before external
publication, but it must not overwrite `bioinfo/meta` without separate
publication authorization.

On the inventory observed on 2026-08-10, a successful v2 full-tree build is
expected to report 16 databases, 30 snapshots, and 141,779 child file records.

## Public CLI contract

The maintained command and operands remain:

```text
biofetch manifest build RESOURCE-ROOT
```

Existing flags retain their spelling and meaning:

```text
--output
--formats
--formats-file
```

Add one tuning option:

```text
--workers int
```

Contract:

- it limits concurrent child-lock readers/parsers, not directory traversal;
- valid range is 1-64;
- default is 4, matching the repository's conservative CephFS hashing
  concurrency;
- `--workers 1` provides a deterministic diagnostic fallback;
- task results and errors are consumed in sorted lock-path order, so changing
  workers cannot change aggregate bytes or error ordering; and
- the option does not authorize raw-file access or CephFS writes.

Do not add `--depth`, `--max-depth`, `--fast`, cache flags, or a list of
hard-coded database paths. Snapshot location is a resource-contract concern,
not an operator tuning parameter.

## Snapshot-aware discovery design

### Reserved non-authority subtrees

The resource contract must state that these directory names are not aggregate
snapshot namespaces and cannot contain an authoritative child lock:

- `raw`: upstream payload owned by the enclosing snapshot lock;
- `tidy`: downstream derived data not owned by biofetch;
- `logs`: operational logs; and
- directory basenames ending in `.part` or `.part.parts`: incomplete
  unpublished staging state.

Discovery returns `filepath.SkipDir` for those directories without enumerating
their children. This also keeps an incomplete snapshot that has `raw/` but no
published lock from triggering a full payload traversal.

### Terminal snapshot roots

Discovery remains depth-independent and single-threaded:

1. visit namespace directories in deterministic lexical order;
2. do not follow directory symlinks, preserving `filepath.WalkDir` behavior;
3. skip reserved non-authority subtrees before reading their entries;
4. when a directory directly contains a regular file named exactly
   `manifest.lock`, record that path as the snapshot authority; and
5. treat that directory as terminal and do not descend into its other
   children.

A malformed lock still claims the directory boundary and is returned to the
normal validator, which reports its path and error. Discovery must not bypass a
malformed parent lock to publish child state hidden below it.

The terminal rule supports both current forms without special cases:

```text
<root>/<database>/<asset>/<version>/manifest.lock
<root>/<database>/<asset>/<dataset>/<version>/manifest.lock
```

It also supports future additional namespace qualifiers, provided no valid
snapshot is nested inside another snapshot. Nested snapshot authorities are
invalid under the fast-path contract.

### Deep-reference behavior

Keep the legacy unrestricted scanner available only as a test and benchmark
reference during implementation. Use it to prove that, for a valid fixture,
snapshot-aware discovery returns the same sorted lock set.

The production fast path does not scan for rogue `manifest.lock` files inside
payload, derived, log, staging, or already authoritative snapshot trees. If
operational evidence later shows a need for that forensic capability, design a
separate no-output `manifest verify` command rather than restoring the cost to
every aggregate build.

## Bounded lock validation

After discovery:

1. sort canonical child lock paths;
2. map them through the existing ordered worker helper using `--workers`;
3. in each task, read the complete lock once, decode TOML, validate every
   common-envelope and `[[files]]` invariant, and calculate SHA256 from those
   same bytes;
4. retain one result or one validation error at the original sorted index;
5. aggregate every validation error in stable path order; and
6. sort and validate snapshots using the maintained aggregate rules before
   rendering any output.

Do not parallelize rendering. TOML, JSON, and TSV continue to be derived from
one in-memory model after every child lock has passed validation.

Concurrency must remain bounded in memory. Four concurrent tasks can hold four
large child lock buffers and decoded models. Tests and acceptance record peak
RSS; a speed improvement that causes unbounded lock retention is not accepted.

## Determinism and failure semantics

The optimized path must preserve these invariants:

- child lock contents, not metadata, determine each recorded SHA256;
- all valid child records are validated on every build;
- filesystem discovery and worker completion order cannot affect output;
- every incompatible child lock is reported in stable path order;
- duplicate identities are evaluated after all compatible locks are read;
- any discovery, parse, validation, identity, render, or write error leaves no
  formal output from that invocation;
- fixed valid inputs and output location produce byte-identical TOML, JSON,
  and TSV; and
- each completed output retains the existing atomic per-file replacement
  behavior.

## Deferred incremental design

Do not add incremental reuse unless snapshot-aware discovery and bounded lock
validation still miss the performance gate.

If later required, incremental reuse needs a separate contract because size
and mtime are not content identities. An acceptable design would require an
atomically maintained authoritative lock index or a full verification mode;
it must detect additions, deletions, renames, and same-size content changes.
An opaque local cache keyed only by path, size, and mtime is not acceptable.

## Dependency-ordered execution slices

### Slice 1: freeze the correctness and performance baseline

- Build a reference binary from commit `4a754c33`.
- Record the sorted child lock inventory, total lock bytes, child record count,
  and an inventory digest before and after every live run.
- Add valid nested-layout fixtures and one three-dataset historical OmniPath
  fixture that reproduces the two aggregate v1 duplicate errors.
- Prove current output/error ordering and atomic failure cleanup before changing
  discovery.
- Invalidate a benchmark run if the start/end inventory digest differs.

Acceptance is the reproducible v1 failure plus the recorded performance
baseline. This slice does not change schemas or runtime behavior.

### Slice 2: implement aggregate v2 dataset identity

Predecessor: Slice 1.

- Change the aggregate schema token to `biofetch-manifest-v2`.
- Read optional child `dataset`, emit it in TOML/JSON, and add TSV `Dataset`
  between `Asset` and `Version`.
- Change identity, sorting, duplicate messages, and model equality to include
  dataset.
- Keep child locks without dataset valid and omit the optional TOML/JSON field.
- Reject an explicitly present empty or non-canonical whitespace-padded
  dataset.
- Make the three-dataset fixture succeed as three snapshots while continuing
  to reject two locks with the same complete v2 identity.

Acceptance is one deterministic v2 model across TOML, JSON, and TSV, with no
performance or discovery change in this review slice. Do not add license or
query fields here.

### Slice 3: implement snapshot-aware discovery

Predecessor: Slice 2, so the exact production inventory can become a successful
v2 acceptance input.

- Add reserved subtree pruning and terminal snapshot boundaries.
- Preserve symlink behavior and stable path sorting.
- Cover incomplete snapshots containing a large/sentinel `raw/` subtree.
- Compare the new lock set with the legacy deep scanner on valid fixtures.
- Measure discovery separately from lock validation.

This slice owns the largest expected speedup and should be benchmarked before
adding concurrency. It must not change v2 model bytes for the same discovered
lock set.

### Slice 4: add ordered bounded lock validation

Predecessor: Slice 3.

- Add `--workers` with default 4 and range 1-64.
- Reuse the repository ordered worker helper.
- Preserve aggregated validation errors in sorted path order.
- Compare `--workers 1`, `4`, and `8` on the exact CephFS root; retain 4 as the
  default unless current measurements show a repeatable regression.
- Run the race detector for `internal/manifest` and the shared parallel helper.

Acceptance requires identical v2 bytes and error order at workers 1, 4, and 8.
This slice does not alter discovery or schema.

### Slice 5: converge consumers, contracts, and benchmarks

Predecessors: Slices 2-4.

- Audit known aggregate consumers before publication and record their v2/TSV
  compatibility result.
- Update architecture and test contracts with the v2 identity and valid-layout
  fast path.
- Append, rather than overwrite, the 2026-07-17 benchmark evidence.
- Record reference and optimized binaries, commit SHAs, exact root, output
  location, lock inventory digest, attempts, elapsed/user/system time, and peak
  RSS.
- Build all formats twice from the full resource tree into `/tmp`, prove
  byte-identical repeats, and verify the expected complete inventory.
- Keep the published v1 aggregate unchanged until the consumer gate and a
  separately authorized CephFS publication both pass.

Acceptance is a publication-ready v2 candidate under `/tmp`; it is not itself
authorization to replace `bioinfo/meta`.

## Exact verification gates

### Focused offline tests

Tests must cover:

- aggregate schema token is exactly `biofetch-manifest-v2` in TOML, JSON, and
  TSV;
- optional child dataset is preserved in TOML/JSON and omitted when absent;
- TSV exports `Dataset` between `Asset` and `Version`, with an empty field for
  ordinary snapshots;
- absent dataset remains compatible, while explicitly empty and
  whitespace-padded values fail validation;
- CollecTRI, DoRothEA, and KinaseExtra at the same release aggregate as three
  distinct snapshots;
- duplicate rejection uses all four identity fields and its diagnostic names
  dataset;
- deterministic sorting uses database, asset, dataset, version, then path;
- standard and arbitrary-depth dataset snapshot discovery;
- pruning of `raw`, `tidy`, `logs`, and recognized staging directories;
- an incomplete snapshot with payload entries but no lock;
- malformed terminal lock behavior;
- symlink directories not followed;
- identical lock sets between snapshot-aware and legacy discovery on valid
  fixtures;
- deterministic output at workers 1, 4, and 8;
- stable multi-error ordering despite out-of-order task completion;
- qualified duplicate identity rejection after parallel parsing;
- no output on discovery, parse, validation, identity, or render failure; and
- fixed TOML/JSON/TSV bytes across repeated builds.

### Read-only CephFS acceptance

Use unique output directories below `/tmp`. Do not write the resource root or
`bioinfo/meta`.

Run reference and optimized binaries in an interleaved sequence to reduce
storage-load bias. Record at least three optimized runs and at least one
reference completion; a 300-second reference timeout may be retained as a
lower-bound observation.

Required acceptance:

- the optimized median end-to-end time is at most 45 seconds and at least five
  times faster than the paired reference median;
- if every reference run reaches the 300-second timeout, an optimized maximum
  of 60 seconds establishes a conservative five-times lower-bound improvement;
- no optimized run exceeds 90 seconds in the accepted non-concurrent window;
- `--workers 4` does not regress against `--workers 1` by more than 20%;
- peak RSS remains bounded and no more than twice the completed reference run;
- start/end child-lock inventory digests match for every accepted run;
- the full current tree succeeds under v2 and includes distinct CollecTRI,
  DoRothEA, and KinaseExtra snapshots;
- the observed inventory reports 16 databases, 30 snapshots, and 141,779 file
  records when the start/end digest matches the 2026-08-10 input;
- a dataset-free compatibility fixture has the same common snapshot values as
  the v1 reference after excluding the intentional schema token and TSV
  `Dataset` column differences;
- TOML, JSON, and TSV decode to one equivalent v2 model; and
- two consecutive v2 builds at the same output location have identical output
  SHA256 values.

The elapsed thresholds are environment-specific release gates for the observed
node4 CephFS workload, not universal guarantees. If concurrent storage load
invalidates the window, preserve the measurements and rerun in a documented
quieter window rather than weakening correctness checks.

## Risks and mitigations

### Hidden nested locks

Stopping at a snapshot boundary no longer discovers locks illegally nested
inside payload or derived trees. Make terminal snapshot ownership explicit,
retain a legacy deep reference test, and specify a separate forensic verify
command only if an operator use case is demonstrated.

### Incomplete snapshots

A version directory may contain a large `raw/` tree before `manifest.lock` is
published. Reserved subtree pruning prevents that state from recreating the
current traversal cost. The missing snapshot remains absent from the aggregate,
as it is today until a valid lock exists.

### CephFS concurrency regression

Parallel lock reading may contend under load. Keep discovery serial, default to
four workers, expose `--workers 1`, and benchmark 1/4/8 rather than assuming
more readers are faster.

### Nondeterministic errors or output

Workers can finish out of order. Store results by sorted input index, aggregate
errors in that order, and render only after all tasks complete.

### Resource tree drift during measurement

Fetches may update locks while a benchmark is running. Compare start/end lock
inventory digests and discard any run whose input changed.

### Aggregate v2 consumer incompatibility

Readers that require `biofetch-manifest-v1`, decode a closed struct with unknown
field rejection, or use fixed TSV column positions may fail on v2. Inventory
consumers before publication, provide a canonical v2 fixture, require explicit
readback evidence, and retain the published v1 artifact until every required
consumer passes.

### Dataset overloading

Future databases may use a field named `dataset` with different semantics.
Aggregate v2 treats it only as an opaque, typed identity qualifier and does not
interpret allowed values. Do not infer it from paths or reuse it for license,
organism, or query profile.

## Recovery and rollback

- Aggregate v2 and the optimization never mutate child snapshots, so code
  rollback requires no resource recovery.
- `--workers 1` isolates concurrency regressions without restoring deep payload
  traversal.
- If snapshot-aware discovery misses a valid lock, stop publication, preserve
  the benchmark inventory, and restore the legacy discovery implementation
  while correcting the documented layout contract.
- Aggregate outputs under `/tmp` are disposable derived artifacts. Do not use
  them as rollback authority.
- The previously published v1 aggregate remains authoritative until a newly
  built v2 aggregate passes schema, consumer, identity, determinism, and
  publication acceptance.
- If a required consumer cannot accept v2, stop publication and keep v1. Do not
  add a second compatibility writer inside `biofetch`; resolve the consumer or
  reopen the schema decision explicitly.
