# Reactome hardening and OmniPath full-evidence implementation plan

Version: v1.0
Date: 2026-07-31
Status: implemented and locally verified

## Scope

This plan owns two acquisition changes inside `biofetch`:

1. make Reactome `current` release discovery resilient without guessing a
   release; and
2. publish reproducible OmniPath interaction snapshots with complete evidence
   fields and an explicit academic or commercial query identity.

It does not define downstream normalization or cross-database integration.

## Public CLI contract

Live OmniPath interactions use:

```bash
biofetch omnipath interactions fetch \
  --dataset collectri \
  --license academic \
  --organisms 9606 \
  --output /resources/omnipath
```

`--license` accepts only `academic` or `commercial`. Omission resolves to and
records `academic`; the two modes always produce different query fingerprints
and snapshot identities. There is no `all` license and no fallback from
commercial to academic.

`--dorothea-levels` and `--dorothea-levels-file` are valid only for
`--dataset dorothea`. Their default is `A,B,C,D`; level E is not requested.
Callers cannot select arbitrary evidence fields. The maintained profile is
`full-evidence-v1`.

An explicit historical `--version YYYY-MM-DD` continues to use the dated
academic archive. Commercial mode is rejected for archive acquisition.

## OmniPath acquisition protocol

For every requested taxid, acquisition:

1. validates the transient OmniPath interaction capability table;
2. fetches an eight-column lightweight inventory;
3. groups sorted target identifiers into deterministic batches capped at 500
   expected edges, 100 targets, and a 6 KiB encoded URL;
4. downloads at most two batches concurrently;
5. retries 429 according to the greater of `Retry-After` and the configured
   retry wait, and retries 502/503 before recursively bisecting a failed batch;
6. aborts if a singleton target still fails;
7. validates one fixed 23-column header, exact target partitions, JSON
   `evidences` and `extra_attrs`, and DoRothEA A-D values;
8. assembles leaves in deterministic plan order and proves that mandatory edge
   keys have no missing, extra, or duplicate values relative to inventory; and
9. fetches inventory again and aborts publication if its edge count or digest
   changed.

Temporary leaf files and the version staging directory use `.part` names.
They are removed on handled failure and never enter the published snapshot.
A pre-existing staging directory is rejected without deletion so a
crash-interrupted run cannot be silently mixed into a new acquisition.

## Snapshot, lock, and restore contract

The published snapshot payload is exactly:

```text
raw/query_meta.json
raw/<taxid>/interactions.tsv
manifest.lock
```

For full-evidence operations, default run logs live under
`<resource-root>/logs/omnipath/interactions/<dataset>/`, outside the snapshot.

`raw/query_meta.json` is deterministic generated JSON. It contains the UTC
acquisition time, canonical typed query, full SHA256 query fingerprint,
transport profile, start/end inventory identity, and actual leaf plan.
`manifest.lock` carries the same typed values in `[query]` and records the
sidecar SHA256. Final TSV records deliberately have no single replay URL;
replay URLs belong to the locked leaf plan.

`lock` treats the sidecar as the query authority, validates its fingerprint and
snapshot-name suffix, and then validates every final TSV against its edge
digest and leaf counts. It requires exact canonical JSON bytes and rejects
unknown fields so restore can reproduce the sidecar SHA256. It never infers
license, fields, or replay URLs from the TSV. The old two-column capability
TSV remains `legacy-basic`; arbitrary text and malformed or unknown JSON are
errors.

`restore` validates the typed manifest before network access, reconstructs the
sidecar, replays the exact locked leaves into staging, and checks every staged
record's byte count and SHA256. A changed upstream response fails before any
published record or `manifest.lock` is replaced. Record paths must be canonical
children of `raw/`; absolute paths, traversal, duplicates, and existing
symlink components are rejected before any write.

## Reactome current-release discovery

When `--version` is omitted, Reactome mapping queries the official current
database-version endpoint. Status 429 and every 5xx status, including 521, use
the configured total attempt count. Each attempt independently applies the
greater of the configured wait and a valid `Retry-After`; one response cannot
change later attempts.

Exhaustion reports the endpoint, final status (including
`transport-error`), and attempt count. It never guesses or reuses a previous
release. After discovery, files are fetched from the immutable numeric release
directory. Explicit `--version vNN` or `--version NN` bypasses discovery.

## Verification gates

Offline tests must cover:

- academic/commercial identity separation, default academic behavior, A-D
  defaults, level-file scoping, and legacy sidecars;
- 429 waiting, 502/503 split, singleton failure, malformed headers/rows/JSON,
  missing and duplicate edges, and start/end inventory drift;
- deterministic sidecar-based lock rebuild and restore drift leaving the
  manifest and existing files unchanged;
- Reactome 521-to-200, 429 and `Retry-After`, retry exhaustion, final transport
  status, and explicit-version bypass through the fetch orchestrator.

The required repository gate is the canonical `go test`, `go vet`, and
`go build` sequence documented in the test contract. Any live smoke uses only
`/tmp` and must not write CephFS.

## Completion evidence

On 2026-07-31 the canonical repository test, vet, and build commands passed.
The built binary also passed help, version, and Bash completion generation.

A live `/tmp` smoke fetched academic `kinaseextra` interactions for taxid
10116 as `full-evidence-v1`: 23,814 edges were assembled from 52 locked leaf
batches into a 23,815-line TSV. Start and end inventory digests were identical,
the final snapshot contained only the required three payload classes, and an
immediate `lock` rebuild left the manifest SHA256 unchanged. A Reactome
current-release dry run resolved release `v97` and planned the immutable
version directory. No CephFS path was read or written by these smoke tests.
