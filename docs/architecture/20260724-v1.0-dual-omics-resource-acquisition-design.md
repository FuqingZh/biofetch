# Dual-omics resource acquisition design v1.0

Status: implementation authority

Decision date: 2026-07-24

Scope: raw reference acquisition for transcriptomics-metabolomics and later
microbiome-metabolomics products

## Decision summary

The first implementation tranche adds the `chebi`, `rhea`, `jaspar`, `chemont`,
`lipidmaps`, and `hmdb` command families. It adds `kegg metabolic` as a sibling
asset under the existing `kegg` family and extends the existing
`omnipath interactions` selector with CollecTRI and DoRothEA instead of
downloading those datasets a second time.

The first tranche must not add an independent "compound crosswalk" downloader.
ChEBI, Rhea, and licensed KEGG snapshots are raw sources; `bioextract` owns the
ChEBI/KEGG Compound/PubChem/InChIKey crosswalk and other normalized tables.

The 2026-07-24 implementation authorization explicitly removed license gating
from the P0/P1 downloader scope. Source and license facts remain documented,
but `biofetch` does not decide whether the caller may use a reachable bulk or
REST endpoint. HTML scraping remains out of scope.

## Evidence from the current repository and resource tree

The maintained [resource and manifest contract](resource-manifest-contract.md)
assigns versioned raw acquisition, source metadata, and `manifest.lock` to
`biofetch`; parsing, normalization, canonical schemas, and derived tidy tables
belong to `bioextract`.

The current KEGG mapping implementation only declares global `organism` and
`ko_pathway` assets plus organism-scoped gene lists, gene-to-KO,
gene-to-pathway, and identifier conversions
([`internal/kegg/mapping.go`](../../internal/kegg/mapping.go)). The inspected
`kegg/mapping/2026-06/manifest.lock` on CephFS has that same scope. It does not
contain complete COMPOUND, REACTION, ENZYME, MODULE, or their global links.
Directory presence therefore does not establish metabolic-knowledge coverage.

The current OmniPath CLI defaults `interactions` to `kinaseextra` and explicitly
limits v1 to that dataset
([`internal/omnipath/cli.go`](../../internal/omnipath/cli.go)). The inspected
CephFS manifest contains only `kinaseextra` for human, mouse, and rat. It does
not establish CollecTRI or DoRothEA coverage.

It is a capacity estimate, not a contractual byte count; the implementation

## Phase 1 minimum: transcriptomics-metabolomics

Implement in this order:

1. **ChEBI database** — lowest legal and protocol risk, and the canonical
   metabolite vocabulary needed by every later edge.
2. **Rhea database** — adds standardized reaction participants and the
   reaction-to-EC/UniProt/GO evidence bridge.
3. **JASPAR profiles** — independent small static release; document that it
   supplies motif/TFBS evidence only.
4. **OmniPath transcriptional-interaction audit and extension** — inspect
   CollecTRI/DoRothEA availability through the existing API, verify species,
   evidence fields, archive behavior, and commercial-filter output before
   changing the dataset allowlist.
5. **KEGG metabolic** — use the documented REST endpoints, preserve list files,
   acquire entries in batches of at most ten IDs, and apply the existing
   350 ms request interval.

The minimum useful biological chain is:

`TF evidence -> target gene -> UniProt/EC -> Rhea reaction -> ChEBI metabolite`.

Licensed KEGG adds KO/module/pathway context; it is not the sole route to a
working first release.

## Ownership and provenance boundary

### Biofetch

- resolves an upstream release without silently substituting a moving version;
- downloads acquisition-shaped files from documented machine endpoints;
- preserves source URLs, query parameters, license mode, release identity,
  sizes, and checksums in or alongside `manifest.lock`;
- provides `fetch`, `lock`, and `restore` with immutable version directories;
- does not parse records to choose a preferred identifier or merge databases.

### Bioextract

- parses raw source formats into stable Parquet schemas;
- normalizes identifiers, structures, taxonomies, evidence, and directionality;
- builds ChEBI/KEGG Compound/PubChem/InChIKey crosswalks with source and match
  provenance;
- produces TF-target, enzyme-reaction, reaction-compound, and pathway edge
  tables without discarding conflicting evidence.

### Analysis workflows

- consume explicit `biofetch` manifest versions and matching `bioextract`
  dataset versions;
- record those versions in each run;
- distinguish observed measurements, curated relations, motif predictions,
  inferred TF activity, and amplicon-predicted function.

## Reusable engineering components and gaps

| Concern | Current capability | Reuse / required change |
|---|---|---|
| Direct HTTP(S) bulk files | [`internal/shared/staticasset`](../../internal/shared/staticasset/staticasset.go) supports parallel downloads, request spacing, retry, resume, per-file verification hooks, SHA-256 locks, incremental manifests, `lock`, and `restore`. | Reuse for ChEBI, Rhea, JASPAR, LIPID MAPS, NCBI Taxonomy, GTDB metadata, and SILVA release files. Add small source-specific release resolvers and asset declarations. |
| FTP-hosted releases | Existing UniProt code consumes `https://ftp.uniprot.org/...`; the downloader is HTTP(S), not a generic FTP client. | Prefer official HTTPS mirrors of FTP trees. Do not add an FTP protocol client unless an accepted source lacks HTTPS. Directory listing/release parsing remains source-specific. |
| Checksums | Static assets always receive local SHA-256 in `manifest.lock`; verifier hooks and the InterProScan sidecar-MD5 flow can reject corrupt downloads. | Reuse official checksum sidecars where present and retain local SHA-256. Define a shared sidecar parser only after two new sources demonstrate the same format. |
| Release resolution | UniProt, GO, Reactome, InterPro, and KEGG have source-specific resolvers. There is no generic “FTP release” abstraction. | Keep first resolvers source-specific. A shared release-index abstraction is premature until URL/index semantics repeat. |
| REST pagination | No generic pagination/cursor abstraction was found. KEGG and OmniPath use domain-specific clients and endpoint behavior. | Bulk releases avoid pagination for ChEBI/Rhea/JASPAR. Extend the OmniPath client narrowly. If a future source requires pagination, first specify completeness, ordering, cursor persistence, resume, rate limits, and snapshot-consistency semantics. |
| License metadata | OmniPath exposes `--license academic|commercial`; other sources publish license files or terms separately. | Preserve requested OmniPath mode and upstream license files where available. Per the implementation authorization, P0/P1 downloaders do not enforce product entitlement. URL reachability still does not mean “commercially safe.” |

## Required validation gates

Every implementation PR must pass the canonical offline gate:

```bash
GOCACHE=/tmp/biofetch-test go test ./...
GOCACHE=/tmp/biofetch-test go vet ./...
GOCACHE=/tmp/biofetch-test go build -o /tmp/biofetch ./cmd/biofetch
```

It must also add:

1. public CLI contract assertions in
   [`internal/biofetch/cli_test.go`](../../internal/biofetch/cli_test.go);
2. offline HTTP fixtures for latest-version resolution, fixed versions,
   checksum success/failure, retry/resume, partial failure, `lock`, `restore`,
   and `--dry-run`;
3. manifest assertions for database, asset, version, source URL, query/license
   mode, scope, file paths, bytes, and SHA-256;
4. a no-network default test guarantee and no CephFS writes;
5. a read-only real-source acceptance command, run separately and only after
   license/endpoint approval;
6. an aggregate-manifest check after any authorized CephFS publication.

For OmniPath, the acceptance evidence must additionally show the requested
dataset, organism, signed/evidence columns, archive version, and commercial
license filter in the raw query metadata. For KEGG, it must show the licensed
delivery channel and a completeness inventory covering COMPOUND, REACTION,
ENZYME, MODULE, and the selected links before the asset is called complete.

## Explicit non-goals

- No cross-database identifier resolution inside `biofetch`.
- No assertion that a directory name proves analytical coverage.
- No HTML scraping for KEGG, HMDB, MetaCyc, CAZy, or another database.
- No inference that open-source client software licenses all downloaded data.
- No default redistribution of non-commercial or contract-restricted content.
- No representation of JASPAR motifs as observed TF-target regulation.
- No representation of PICRUSt2 predictions as measured metagenomic function.
