# Complex Portal acquisition contract

Version: v1.0
Date: 2026-10-20
Status: current

## Source and scope

Official source: <https://ftp.ebi.ac.uk/pub/databases/intact/complex/>.
The [official download guide](https://www.ebi.ac.uk/training/online/courses/complex-portal-quick-tour/getting-data-from-complex-portal/)
describes species-specific ComplexTab files, separate predicted files and
PSI-MI XML distributions. HTTPS download requires no authentication.

Data are CC0; software licensing is separate. See the
[provider terms](https://www.ebi.ac.uk/complexportal/about#license_privacy)
and the authors' [2025 database paper](https://doi.org/10.1093/nar/gkae1085).
Citation: Balu S. et al., *Complex portal 2025: predicted human complexes and
enhanced visualisation tools for the comparison of orthologous and paralogous
complexes*, Nucleic Acids Research (2025). Biofetch releases redistribute no
upstream database bytes.

## Public commands and layout

```bash
biofetch complexportal complextab fetch --output /data/complexportal
biofetch complexportal complextab fetch --output /data/complexportal --version 2026-01-09
biofetch complexportal psi30 fetch --output /data/complexportal --version 2026-01-09
biofetch complexportal complextab lock /data/complexportal/complextab/2026-01-09
biofetch complexportal complextab restore /data/complexportal/complextab/2026-01-09
```

The default version, or `current`, resolves the latest valid `YYYY-MM-DD`
directory at the official root. Explicit dates bypass latest discovery.
Payload URLs always use the resolved dated directory; moving `current` URLs
never appear in locks. Invalid dates and path-like versions are rejected.

| Asset | Raw content | Scope |
| --- | --- | --- |
| `complextab` | `index.html`, `<taxid>.tsv`, `<taxid>_predicted.tsv` | Every listed species and predicted set |
| `psi30` | `complexesMIF30.zip` | Official complete XML 3.0 archive |

Files live under `complexportal/<asset>/<date>/raw/`. The snapshot lock uses
`database = complexportal`, `source = embl-ebi-complex-portal`, and matching
`version` / `version_token` dates. It records paths, fixed URLs, bytes and
SHA256 for every acquired file. Archives remain compressed and unmodified.
The two assets are alternative representations with overlapping content;
their sizes must not be interpreted as distinct biological record counts.

For the 2026-01-09 release, the full ComplexTab set contains 29 TSV files,
15,165,729 payload bytes plus its directory index. The XML archive contains
20,580 members, is 161,388,099 bytes compressed and 1,489,181,015 bytes
uncompressed. These are measured release facts, not hardcoded future
inventory limits.

## Acquisition and recovery

Reuse the shared downloader, concurrency controls, retry/resume and lock
engine. The default is two download workers, five payload attempts and
three seconds between retries. Metadata reads have a 30-second timeout and
2 MiB size bound; a failed discovery reports the error for command retry.
The index parser accepts immediate same-origin children, deduplicates links,
and ignores parent/sort/foreign links. Unrecognized TSV names and empty
inventories fail rather than silently reducing the acquired set.

Fetch validates TSV headers and row shape; XML verification reads all archive
members and checks ZIP integrity without extraction. The final lock requires
the entire discovered inventory. A failed download publishes no complete
lock. Dry-run resolves and validates metadata but creates no snapshot files.

Lock reads the saved inventory offline and requires every declared file.
Restore uses that inventory and the authoritative lock, never current-release
discovery. If the saved index is missing or damaged, restore retrieves only
its fixed URL and requires the original size/SHA256 before using it. Restored
payloads also require the original SHA256 before replacement. Repeat fetch on
an already locked snapshot follows this same immutable restore behavior.

An old development snapshot containing only curated TSVs, but an index that
also lists predicted TSVs, is incomplete under this full-source contract.
It is preserved and rejected; acquire the complete release in a separate
output root. Existing biological consumers must explicitly choose curated or
predicted evidence rather than treating their mixture as equivalent.

Normalization, biological interpretation and publication to a downstream
catalog belong to bioextract and its consumers. This downloader does not
change those contracts or existing resource-release metadata.

## Verification

Offline fixtures cover fixed/current version resolution, malformed dates and
inventories, all-species plus predicted coverage, link confinement, no-write
dry runs, complete fetch/reuse, missing-file lock rejection, offline
lock/restore, missing-index recovery, digest drift, malformed payloads,
tampered/legacy locks and symlink rejection. Public CLI tests cover both
asset families and all three actions.

Live acceptance uses the released binary, fixed upstream version and a
separately authorized resource directory. Verify snapshot inventory and
per-file hashes after acquisition; CLI success alone is insufficient.
